# Перенос новой игры

[中文](NEW_GAME_PORTING.md) · [Главная](../README.ru.md) · [Среда](SETUP.ru.md)

Руководство для разработки ещё не поддерживаемой игры. Для готовой адаптации
достаточно её README; ИИ не требуется.

## Подготовьте материалы

- Название, версию, обновления и дополнения игры.
- Законно приобретённые оригиналы, патчи и рабочие копии для преобразования.
- EXE игры, LiarsoftTool, Ren'Py 8 SDK и выходной каталог.
- Изображение, звук и действия оригинальной игры для сравнения.

Подготовьте TSC и ресурсы через LiarsoftTool. Сходство каталогов само по себе
не означает совместимость с существующей адаптацией.

## Порядок разработки

1. Подтвердите версию, точку входа, диалект команд и структуру ресурсов.
2. Реализуйте запуск, титул и первую сцену; проверьте фон, персонажей, текст, речь и выборы.
3. Завершите меню, сохранения, откат, системный прогресс и галереи.
4. Проверьте другие маршруты, добавьте тесты и пользовательскую инструкцию.
5. Затем занимайтесь Android и проверкой на устройстве.

Повторно используйте `runtime/` и `port_template/`; различия игры храните отдельно.
Неизвестное поведение проверяйте по EXE, сценариям и оригиналу, а не угадывайте
по другой игре.

### Проверка UI-ресурсов

Сначала определите назначение каждой группы. [Общий шаблон](../port_template/README.ru.md)
содержит список: `dt*` — изображения сохранений, `nonbl` — цифры страниц,
`compane` — игровая панель, `confscrn` — меню правой кнопки, `savescrn` — сохранения
и загрузка. При других именах проверяйте реальные ресурсы этой игры.

Сохраняйте и читайте холст, координаты и размеры `.meta.xml`. Не угадывайте
координаты и не центрируйте всё подряд. Для слотов проверяйте цифры и даты
`saveconf`. Имена кнопок, действия, выбранное состояние и наведение проверяются
отдельно. Сохраните исходное главное меню; только его пункт настроек соединяется
с существующим Text Settings, а не заменяет всё меню.

## Запрос для ИИ

Заполните версию и пути:

```text
Перенеси следующую игру CodeX RScript с помощью rscript2renpy.

Игра и версия: <название, обновления, дополнения>
Каталог адаптера: rscript2renpy/<slug>
Ресурсы оригинала: <путь только для чтения>
EXE оригинала: <путь только для чтения>
Рабочая копия ресурсов: <доступный для записи путь>
Языковые патчи: <метка=путь или отсутствуют>
Репозиторий rscript2renpy: <путь>
Репозиторий и CLI LiarsoftTool: <пути>
Ren'Py 8 SDK: <путь>
Выходной проект: <новый путь>

Нужен воспроизводимый генератор, чтобы владельцы той же версии игры могли
самостоятельно собрать проект по README.

Прочитай AGENTS.md обоих репозиториев, README и общий шаблон, проверь имеющиеся
изменения. Установи версию, диалект TSC, точку входа и ресурсы, затем перечисли
необходимые функции адаптации.

Требования:
1. Оригиналы только для чтения; преобразования на копиях. Генератор принимает только TSC.
2. Проблемы преобразования исправляй в LiarsoftTool. Общее — в общих модулях, различия — в адаптере.
3. Непереносимое напрямую поведение сверяй с EXE, сценариями и оригиналом. Не угадывай команды и эффекты.
4. Сначала запуск, титул и первая сцена, затем меню, сохранения, системный прогресс и галереи.
5. При визуальной неопределённости спроси меня. Неизвестное перечисляй явно, сюжетные команды молча не пропускай.
6. Не коммить ресурсы, готовые проекты, сохранения, личные пути и ключи.
7. Добавляй тесты. Общие изменения проверяй на существующих адаптациях; прохождение и Android проверяются отдельно.
8. В README игры опиши версию, среду, ресурсы, команду сборки, патчи и необходимые ограничения.
9. Проверенные независимые задачи коммить локально. Без запроса не отправляй изменения и не публикуй релизы.

Сначала изучи материалы и существующую реализацию, затем приступай.
```

## Проверка результата

Генератор должен иметь понятный `--help`, принимать ресурсы и выходной каталог
и не зависеть от личных путей сопровождающего. Исправления нужны в исходниках,
а не только в вручную отредактированном готовом проекте.

Главный README ссылается на руководство игры. Анализ EXE хранится отдельно
в каталоге игры: версия, хеш, ключевые адреса, неизвестные детали; сам EXE не коммитится.

Общие проверки — в [документации](README.ru.md). Успешные тесты и lint не заменяют
сравнение реальных маршрутов, изображения и звука с оригиналом.
