# Техническая справка: update, эффект 2

[中文](UPDATE_EFFECT2.zh.md) | [English](UPDATE_EFFECT2.en.md) | [Русский](UPDATE_EFFECT2.ru.md) | [日本語](UPDATE_EFFECT2.ja.md)

[Документация](README.ru.md)

2026-10-11 только чтением проверены пять пользовательских PE32 EXE. Эффект 2 — упорядоченная замена пикселей 4×4,
не мозаика и не увеличение/уменьшение. Старый вызов Pixellate по запросу оставлен комментарием и не исполняется.
Выводы ограничены этими сборками.

## Вызовы и таблица

Все адреса VA. Проверяется второй элемент update и непрозрачная ветвь mode 18;
само наличие одинаковой таблицы не доказывает семантику команды.

| Игра / EXE | Ветвь update 2 → переход | Копирование пикселей | Таблица 16 WORD |
| --- | --- | --- | --- |
| Forest / Forest.exe | `41c278[2] → 41c1be → 43ec10` | `431f00`; вызов из `42f393` | `463300` |
| Khime / KhimeDL.exe | `422290[2] → 4221d6 → 4482c0` | `439520`; вызов из `436983` | `46e100` |
| CannonBall / Cannonball.exe | `416404[2] → 41635d → 42bdb0` | `4207e0`; вызов из `41deb3` | `450070` |
| Evermaiden / startup_jp.exe | `43b5e4[2] → 43b50b → 4531d0` | `447077` непрозрачная inline-ветвь, `4471d0..4471f9` копирование) | `4eb550` |
| Kagerou / kagerou.exe | `41e7e0[2] → 41e726 → 4504e0` | `4437d0`; вызов из `440c33` | `47ef38` |

Strength >> 4 выбирает WORD; (x%4)+4*(y%4) выбирает бит. Единица копирует новый пиксель, ноль оставляет старый.
Во всех пяти таблица одинакова:

```text
FFDF EFDF 6FDF 6FD7 6BD7 6BD6 6B56 6A56
2A56 2A52 0A52 0A12 0812 0810 0800 0000
```

Сила кадра floor((Step-frame)*255/Step), всего Step−1 кадров, затем целиком новый экран.
Step=0 на входе превращается в 10; Step=1 или Wait=0 не создают номинального ожидания.
timeGetTime/GetTickCount измеряют миллисекунды, не сотые секунды: max(0,Step-1)*Wait/1000.
Стоимость рисования, Sleep и лишняя задержка строгого > Wait не моделируются.
Остальное совместимое время других эффектов этой проверкой не менялось.

## Реализация и проверка

runtime/effects.rpy хранит маски и последовательность; runtime/shaders.rpy выбирает пиксели старого/нового экрана.
Сначала исходный виртуальный холст, затем плавное масштабирование целиком, чтобы масштаб окна не менял сетку.
Эффект использует runtime/03_rscript_gfx.rpy.
tests/test_shared_port.py /path/to/renpy-sdk проверяет стадии 1/3/10/16/32 шагов, направление 4×4,
финальный кадр и окна 700×525 / 1000×750 по эталонным битовым картам в изолированных Forest/Khime GL2.
Отдельные modern/Kagerou-проверки подтверждают вызов реализации, нулевые шаги/ожидание.
Это не покадровое сравнение с EXE. Android GPU, полное прохождение и старые сохранения проверяются отдельно.
