# 通用 RScript 文本折行

Forest 与 khime 的普通对话、追加对话、`_oload` 统一使用 `RScriptText`。
禁则集合和算法在 `runtime/rscript_wrap.py`；与 Ren’Py 的衔接在
`runtime/00_rscript_wrap.rpy`。规则不随语言切换，不寻找单词边界。

## 规则与宽度

`NO_LINE_START`、`NO_LINE_END` 精确采用需求给定的 Unicode 集合，包括
U+3000、U+00A0；归属独立保存，`“` 同时属于两者。

按真实字形前进量计算；字形末端等于边界时可放入。2026-10-03 根据原游戏
对照和用户确认，改为允许**从行边界内开始的普通字形**完整显示，末端可自然
延伸，不能再只因累加后超过边界就把它移到下一行。溢出依次处理：

1. 本行尚未悬挂，且当前字形起始位置仍小于行边界，或当前字形禁止行首：
   保留在本行，使用唯一悬挂额度。两种情况都要求本行尚未悬挂；普通字形
   起始位置恰好等于边界则不适用。
2. 否则，紧邻的上一字形禁止行尾：仅将该字形移到下一行，继续处理当前字形。
3. 否则，在当前字形前断行。

新行重置悬挂额度。不在文本结束时回退开括号，也不递归回退整串。
超宽首字形强制接收；若回退会留下空行，则直接在当前字形前断行。
零宽字形保留，始终前进。没有负间距、标点压缩或字符替换；百分号也不再被双写。

常规行宽是**正文基础字体、字号的全角空格前进量 × 配置字数**。
通用默认 19；Forest 保留 `_say` 19、`_oload` 20 和现有独立配置。
行内字号、字体、粗体、斜体、字距和图片改变各自的实际前进量，不改变基础行宽。

## 原生布局衔接

本机检查和测试版本：Ren’Py **8.5.3.26051504**。

Ren’Py `renpy/text/text.py` 在 `Layout` 中完成字体塑形、字距处理和图片度量，
随后调用 `textsupport.linebreak_nobreak`。适配器只对 `RScriptText` 接管这一阶段，
读取已经塑形的 `Glyph.advance`，设置断点；不拿包围盒宽度或 East Asian Width
估算，不重做字体塑形。普通 Ren’Py 菜单文本不受影响。

`layout="nobreak"` 关闭二次软换行。最终绘制布局沿用虚拟布局的断点；文本框
不再用常规行宽限制 Text 的外框，Ren’Py 按悬挂后的实际尺寸分配显示空间。
不改写传入 `say` 屏幕的 `what`，保留 `id "what"`，避免破坏逐字显示校验。
当前 SDK 没有公开的自定义断行回调，因此这是一处局部、按文本类型启用的内部
接口适配；升级 SDK 后应重新运行原生测试，而不是假定内部接口永远不变。

解析控制码后才折行。`^n` 是字形边界的布尔断行标记：同一边界重复标记合并，
开头与末尾不制造空白行；两侧空格保留，有空格的段落不是空段落。合并断行时
保留颜色、链接、等待等标签的顺序，不移动标签、不在标签中插入换行。
姓名牌仍独立布局；`^g`、`^a`、Wiki 图片/链接使用原有处理，正文图片按最终尺寸
计入宽度；`^m`、现有语音、等待和行距设置保留。

`|正文[注音]` 在公共控制码解析器中转换为 Ren'Py 原生 `{rb}/{rt}`，普通对话、
追加、文本对象共用，不限于现代 `TXT`。注音继承正文字体、颜色与粗斜体，字号为
所在正文的一半；布局按实际字形高度设置上移及留白，不依赖 Ren'Py 的默认 ruby 样式。
正文与注音作为不可拆的折行单元，仅正文前进量计入行宽，避免注音单独换到下一行。
含注音的文本先做一次无纹理原生度量，再用新的匿名样式布局；普通文本无额外度量。
使用全块最大注音高度留白，并非逐行复刻原引擎的 ruby 参数。

Wiki 链接只添加链接样式，不继承 Ren’Py 默认链接字体；保留周围正文和行内
标签的字体、字号、粗斜体、字距及逐字显示速度。开关 Wiki 不应改变相同文本的断点。

混合文本使用比例字体的真实前进量。例如在内置 Noto Sans 字号 22 下，
`之后，我俩跑到Royal Host餐厅，就桃色电影` 的“电”结束位置约 414.7 像素，
小于常规 19 字宽的 418 像素；“影”在边界内开始，因此完整显示到约 436.7
像素，不再单独另起一行。无需将默认字数改为 20，也不压缩字符或增加负间距。
显式 `^n` 仍强制断行，不能为凑齐行数而删除。异常配置或更多文本仍可能超出
固定高度的对话框；这一修复不引入自动分页或改变对话框高度。
Forest 当前默认使用这一 Noto Sans CJK JP Regular；黑体仍可选，但其
英文度量在这句中较宽，仍可能多折一行。实测比较见
[字体分析](FOREST_FONT_ANALYSIS.md#混合文本修复选用英文更窄的默认字体)。

追加对话将此前完整文本与新片段（及 `{fast}`）交给同一原生布局器，重新确定
全部断点。字体、字号、行宽、行距、语言或 Wiki 配置变化使已有文本对象的
布局失效，重建其匿名样式及文本标签，避免 `_oload` 保留旧字体/旧图片尺寸。

## 人工边界示例

下面假设各字符前进量相同，基础行宽为 **2 个全角字**；结果中的 `↵` 表示行界，
不是显示字符。实际比例字体的断点应以字形前进量为准。

| 输入 | 应显示为 | 检查点 |
| --- | --- | --- |
| `甲乙` | `甲乙` | 恰好到边界 |
| `甲乙丙` | `甲乙↵丙` | 普通字溢出 |
| `甲乙。！` | `甲乙。↵！` | 只悬挂一个标点 |
| `甲（乙` | `甲↵（乙` | 回退一个开括号 |
| `甲（` | `甲（` | 文本结束不触发回退 |
| `甲（。` | `甲（。` | 当前标点悬挂优先 |
| `甲乙“` | `甲乙“` | 双重归属字符先悬挂 |
| `甲乙“丙` | `甲乙↵“丙` | 下次溢出再回退它 |
| `^n甲^n^cy^n乙^n` | `甲↵乙` | 连续断行合并、控制事件保留 |

还应在游戏中检查混合中日俄文本、比例字体下的 `WiWi`、全角空格/NBSP，
以及 `{size}`、粗斜体、Wiki 链接、`gfNNN`/`ggNNN` 的切换。
特别检查居中对话、文本对象、追加后整句的布局，以及悬挂标点在桌面/Android
是否有裁切。异常大的用户字号/行宽配置仍可能超过物理屏幕；折行器不压缩字符。

## 可重复测试

```bash
python3 -B tests/test_text_wrap.py
python3 -B tests/run_native_text_wrap.py /opt/apps/renpy
python3 -B tests/test_runtime.py
python3 -B tests/test_port_template.py
python3 -B tests/test_forest_validation.py
python3 -B tests/test_forest_builder.py /path/to/converted-Forest
python3 -B tests/test_khime_builder.py /path/to/converted-khime
/opt/apps/renpy/renpy.sh /path/to/generated-Forest lint
```

第一项是给定前进量的算法测试，包含零宽、超宽与穷举前进/保字检查；第二项
调用真正的 Ren’Py 字体塑形和文本布局（不启动图形窗口），包括字体/字号切换、
图片尺寸、标签、真实追加对话执行路径及已有对象重排。
生成器测试与 lint 验证生成/语法/资源引用，不等于游戏视觉、语音或设备验证。
