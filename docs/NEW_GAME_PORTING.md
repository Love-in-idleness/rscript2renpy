# 新游戏移植指南

[返回主说明](../README.zh.md) · [环境配置](SETUP.md)

[Русский](NEW_GAME_PORTING.ru.md)

本页用于开发尚未支持的游戏。已有适配直接按对应游戏 README 构建，不需要 AI。

## 准备资料

- 游戏名称、版本、更新和特典。
- 合法持有的原游戏与补丁，以及用于转换的副本。
- 原游戏 EXE、LiarsoftTool、Ren'Py 8 SDK 和输出目录。
- 能对照的原游戏画面、音频与操作过程。

先用 LiarsoftTool 准备 TSC 和资源。新游戏不能只因目录相似就套用现有适配。

## 开发顺序

1. 确认版本、入口、指令方言和资源布局。
2. 做通启动、标题、首段剧情，同时检查背景、立绘、文字、语音和选择。
3. 完成菜单、存读档、回滚、系统进度和鉴赏。
4. 检查其他路线，补充自动测试和用户说明。
5. 最后处理 Android 打包和实机问题。

通用代码复用 `runtime/` 与 `port_template/`，游戏差异放在新目录。
不能确认的行为从本作 EXE、脚本和实际效果核对，不凭其他游戏猜测。

### 界面资源检查

先记录每类素材的用途，再实现界面。通用模板中的
[界面资源分工](../port_template/README.zh.md#界面资源分工)列出检查清单：
`dt*` 是存档图像，`nonbl` 是翻页数字，`compane` 是游戏控制栏，
`confscrn` 是右键菜单，`savescrn` 是存读档界面。
缺少对应目录或使用不同命名时，仍须按本作实际资源逐项核对。

保留并读取 `.meta.xml` 的画布、位置和尺寸；不能只复制图片、猜坐标或全部居中。
存档槽位还要检查 `saveconf` 的数字和日期组件。按钮名、动作、选中与悬停状态
分别核对，不把外观相似的按钮接到同一功能。保留原作主菜单，
只将其中的“环境设置”入口连接到已有的 Text Settings，不替换整个主菜单。

## 可复制的 AI 提示词

填写路径和版本后使用：

```text
请使用 rscript2renpy 移植以下 CodeX RScript 游戏。

游戏名称和版本：<名称、更新、特典>
适配目录：rscript2renpy/<slug>
原游戏资源：<只读路径>
原游戏 EXE：<只读路径>
资源转换副本：<可写路径>
语言补丁：<语言标签=路径，没有则写无>
rscript2renpy 仓库：<路径>
LiarsoftTool 仓库和 CLI：<路径>
Ren'Py 8 SDK：<路径>
输出工程：<新路径>

目标是提供可重复运行的生成器，让持有同版本游戏的用户按 README 自行构建。

先阅读两个仓库的 AGENTS.md、项目 README 和公共模板，检查已有修改。
确认版本、TSC 方言、入口和资源，再列出需要适配的功能。

要求：
1. 原件只读，转换在副本中完成；生成器只接受 TSC。
2. 资源转换问题在 LiarsoftTool 修复。通用能力写入公共层，游戏差异写适配目录。
3. 不能直接复用的行为必须核对本作 EXE、脚本和实际表现，不猜指令或效果。
4. 先做通启动、标题和首段剧情，再处理菜单、存读档、系统进度和鉴赏。
5. 视觉判断不确定时问我。未知功能明确列出，不静默跳过剧情指令。
6. 不提交游戏资源、生成工程、存档、个人路径或密钥。
7. 为新增行为添加测试，公共修改检查已有适配；实际游玩和 Android 单独验收。
8. 游戏 README 写支持版本、环境、资源准备、构建命令、语言补丁和必要限制。
9. 独立任务验证后本地提交；未获要求不推送、不发布。

请先检查资料和现有实现，再开始工作。
```

## 交付检查

生成器必须有清晰的 `--help`，接受资源与输出目录，不依赖维护者机器上的路径。
修复写回源码，不能只留下一个手工改好的输出工程。

游戏 README 从主 README 链接。原生依据放在游戏目录的开发参考，
记录文件版本、哈希、关键地址和未知项，不提交原 EXE。

公共测试入口见 [文档目录](README.zh.md#开发检查)。
测试和 lint 通过后，仍需对照原游戏检查实际路线、画面和音频。
