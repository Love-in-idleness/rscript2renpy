Только чтение пользовательского KhimeDL_CHS.exe, без исполнения/распространения.
SHA-256 `522bec3e93340ffd3bdb24ba98cfb775f80df9d85460819da840d824ad4822a8`.
PE32, ImageBase `0x400000`; ниже VA этой сборки, не всех версий.

## Основания

- Диспетчер `0x420825/0x420850/0x420863/0x4208cc` вызывает setclk/setclksys/resetclk/setlink
  в `0x423910/0x423940/0x4239a0/0x4239c0`.
- setclk: `0x4222b0 → 0x406860`, поля +0x30 включение, +0x34 наведение, +0x52 результат,
  +0x36 обычный/системный класс. setclksys: `0x4222e0 → 0x4068d0`, класс 1.
- setlink: `0x422370 → 0x4069b0`, последний аргумент выбирает слот +0x38/+0x3a,
  координаты +0x40/+0x44 и +0x48/+0x4c. Изображения находятся в this+0x58/this+0x5c, не в теле this+0x54.
- Наведение `0x40a000` читает +0x34: 0 без изменения, 1 инверсия (renderer 13),
  2 побеление (renderer 4, уровень 64), 3 скрытие тела (renderer 23).
  `0x40a065–0x40a097` показывает ненулевые картинки обоих слотов; `0x40a0c0` восстанавливает тело и скрывает их.
- `0x405eb4/0x405ecb/0x405ee2` связывают клик/вход/выход. `0x435c60` проверяет
  прямоугольник +0x3c…+0x48 и alpha тела, не setlink. load `0x409aa0` меняет положение тела,
  `0x4098a0` берёт его прямоугольник для слота 0, последующий setlink независимо ставит связанные картинки.
- cls `0x4067ce → 0x406a90` с force 1 сбрасывает клик и ID обоих слотов (+0x30/+0x38/+0x3a).
  В очереди метаданные сбрасываются сразу, рисование позже. resetclk 0 пропускается в `0x4239a4`, не сбрасывает всё.

## Адаптация

Раньше слот 0 заменял тело/точку попадания, а cls сохранял старые привязки. Подсказка 41 в 0501
становилась старой кнопкой CG; треки 0401 без setlink использовали прежние картинки/координаты;
0301 также страдал. Khime теперь задаёт rscript_click_link_is_preview и rscript_click_native_effects.
Общий runtime проверяет позицию/alpha тела, преобразует его и отдельно показывает два связанных изображения;
cls нативного диалекта очищает привязки. Forest/обычный диалект сохраняет прежнее замещение.
Правила одного EXE не навязываются всем версиям; сохранения игрока не менялись и не удалялись.
Вход дополнения распознаёт тело 9006, не старое изображение наведения 9106.

tests/test_shared_port.py /path/to/renpy-sdk проверяет очередь очистки, повторный слой подсказки,
треки без связанных картинок, независимые координаты и оба слота. Графические проверки —
вход/выход мыши, оба превью, пиксели и результат клика. Три реальных меню Khime и старые сохранения
ещё проверяются вручную. tests/test_khime_zero.py проверяет вход дополнения и возврат к титулу.
