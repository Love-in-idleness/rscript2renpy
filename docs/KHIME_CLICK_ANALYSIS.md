# Khime 图片菜单与鼠标命中

只读分析用户提供的 `KhimeDL_CHS.exe`，不运行或分发 EXE。
SHA-256：`522bec3e93340ffd3bdb24ba98cfb775f80df9d85460819da840d824ad4822a8`。
PE32，ImageBase `0x400000`，以下地址均为 VA。

## 原引擎证据

- 指令分派 `0x420825/0x420850/0x420863/0x4208cc` 分别调用
  `setclk/setclksys/resetclk/setlink` 的 `0x423910/0x423940/0x4239a0/0x4239c0`。
- `setclk` 经 `0x4222b0 → 0x406860` 写对象状态 `+0x30`（启用）、
  `+0x34`（悬停模式）、`+0x52`（返回值）、`+0x36`（普通/系统分类）。
  `setclksys` 经 `0x4222e0 → 0x4068d0`，分类设为 1。
- `setlink` 经 `0x422370 → 0x4069b0`，按最后一个参数分别写两槽的
  图号 `+0x38/+0x3a` 和坐标 `+0x40/+0x44`、`+0x48/+0x4c`。
  实际加载对象为 `this+0x58/this+0x5c`，不是按钮本体 `this+0x54`。
- 悬停回调 `0x40a000` 从 `+0x34` 选择本体效果：0 不变、1 反色
  （renderer 13）、2 泛白（renderer 4、等级 64）、3 隐藏本体
  （renderer 23）。随后 `0x40a065–0x40a097` 遍历两槽，显示非零图号。
  离开回调 `0x40a0c0` 恢复本体颜色并隐藏两槽。
- 本体注册鼠标回调：`0x405eb4/0x405ecb/0x405ee2` 分别绑定点击、进入、
  离开函数。`0x435c60` 用该对象的矩形 `+0x3c…+0x48` 和像素 alpha
  检查命中；不读 `setlink` 的坐标。`load` 的 `0x409aa0` 更新本体位置，
  `0x4098a0` 从本体取得矩形供槽 0 使用，后续 `setlink` 才独立设置关联图位置。
- `cls` 的 `0x4067ce → 0x406a90` 以强制参数 1 复位点击启用位和两槽
  图号（`+0x30/+0x38/+0x3a`）。队列模式也先复位元数据，绘制可稍后执行。
  `resetclk 0` 仍由 `0x4239a4` 跳过，不等于全局复位。

## 移植修复与边界

之前 Khime 没启用公共原生点击语义：把槽 0 当作本体替换图及命中位置，
并在 `cls` 后保留旧绑定。于是 0501 的提示图层 41 重新成为旧的“画像鉴赏”
按钮；0401 曲目无 `setlink` 时使用旧图片和坐标；0301 场面回想也受同一问题影响。

Khime 现在声明 `rscript_click_link_is_preview` 与 `rscript_click_native_effects`。
公共运行时用本体位置及透明遮罩命中、按模式变换本体、独立显示两槽关联图；
原生方言的 `cls` 同时清除绑定。Forest/默认方言保留既有替换图语义，
不把本 EXE 的规则强套给其他引擎版本。没有修改或清除玩家存档。
归省入口改为识别标题按钮本体 `9006`，不再依赖旧的悬停替换图 `9106`。

回归：`tests/test_shared_port.py /opt/apps/renpy` 覆盖队列清除、提示图层复用、
无关联图的曲目按钮、关联图与命中坐标分离及两槽显示；独立图形测试覆盖鼠标
进入/离开、双关联图、像素和点击返回值。实际 Khime 三个菜单及旧存档仍需人工检查。
`tests/test_khime_zero.py` 同时检查新悬停模式下的外传入口及返回标题。

此次本机整套资源 smoke-check 的边界：`0_Package/星空流星/Khime` 的
`scr/0000.tsc:5` 仍是旧式未引用字符串 `*jump 1 0`，被当前解析器拒绝；
`KhimeKusaritop` 的场景编译通过，但缺少 `grps/confscrn` 元数据使界面资源
断言失败。本次只同步已核对无手工改动的运行时/覆盖层，没有重写这些资源。
隔离 lint 退出码为 0，仍报告既有重复 default、不可达语句及 Forest 非 ASCII 文件名。
