ソースの役割を説明します。既存作品の構築には各ゲーム README を使ってください。

## 役割分担

| 場所 | 責任 |
| --- | --- |
| LiarsoftTool | アーカイブ、GSC/TSC、文字コード、画像・音声変換 |
| `runtime/` | 命令、レジスター、層、文字、音声 |
| `port_template/` | コンパイル、パッチ整列、資源配置、GUI |
| ゲームディレクトリ | 方言、版検査、既定レイアウト、専用動作 |
| 生成工程 | ビルド結果。共通コードの保守場所ではない |

共通修正は公共層、作品差分は適応層へ。共通コードの長期複製や配置後の文字列置換はしません。

## 工程生成

準備済み TSC を読み、シーンをコンパイルし、`assemble_port` で配置します。事前の資源変換は LiarsoftTool で行います。共通配置はメディアコピー、設定生成、対応 `.rpyc` 消去を担当します。原資源・パッチ・出力は重複できません。途中失敗を解決してから再構築してください。

`game/scr/`、`game/engine/`、`game/tl/<言語>/` を使い、メディアは原ディレクトリ名を保持します。

## 言語パッチ

| 作品 | 方針 |
| --- | --- |
| Forest | 翻訳・字幕整列。5000 は全置換 |
| 腐り姫 | 翻訳・字幕整列。外伝資源は分離 |
| Evermaiden、CannonBall、霞外籠逗留記 | 全シーン置換 |

パッチを原版に混ぜません。訳のないシーンは原版に戻り、フローの異なる言語のセーブ互換を仮定しません。

## ランタイムと GUI

文字、音声、クリック、描画キューを共有し、方言は明示設定で選びます。バイト配置だけからアニメーション、座標、時刻の意味を推測しません。

`grps_layout.py` は複合画像のメタデータ、`grps_ui.rpy` は設定・選択・保存・バーを担当します。原ハードコード UI は検証済みの作品レイアウトで対応。文字速度は既定で遅く、プレイヤー設定、persistent、セーブ場所を作品ごとに分離します。

PC/Android の表示版は `build_port.py` が管理し、普通の更新で Android 最低要件を上げません。スクリーンショット、タッチ、パッケージは実機確認が必要です。

## 開発時の確認

共通変更は `test_runtime.py`、`test_port_template.py`、`test_shared_port.py` の後、対象作品を検査します。[コマンド一覧](README.ja.md#開発時の確認)を参照してください。SDK 更新後は native 文字・UI テストも再実行し、完全プレイは別に記録します。
