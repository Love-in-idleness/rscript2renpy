# Правила репозитория

## Границы изменений

- Проверьте состояние Git, сохраните существующие правки и прочитайте затронутые модули и руководства игр.
- LiarsoftTool отвечает за распаковку и преобразование ресурсов; этот репозиторий — за генерацию Ren'Py из TSC, среду исполнения и интерфейс.
- Общий код размещайте в `runtime/` и `port_template/`, различия игр — в адаптерах. Исправляйте исходники, а не только результат генерации.
- Неизвестное поведение устанавливайте по EXE, сценариям и работе соответствующей игры, не по аналогии с другой.
- Оригиналы доступны только для чтения; для преобразования и тестов используйте копии. Не коммитьте игровые ресурсы, проекты, сохранения, личные пути и ключи.
- Перед перезаписью проверьте ручные правки. Сохраняйте проверку входа и безопасную запись файлов, не расширяйте область очистки.

## Документация

- README предназначен пользователю: назначение, установка, работа, поддержка и существенные ограничения. Технические основания вынесите в справочники.
- Документы проекта ведите отдельно в `.zh.md`, `.en.md`, `.ru.md`, `.ja.md`; файл без суффикса служит выбором языка.
- Согласуйте сведения и структуру четырёх версий. Примеры не должны зависеть от личных настроек сопровождающего или закрытых материалов.
- Удаляйте дневники задач, решения из переписки, историю коммитов и устаревшие числа тестов. Полезные выводы формулируйте как текущее поведение или ограничения.
- Сохраняйте исходные лицензии, авторство и происхождение ресурсов. Для исследования EXE указывайте образец и границы выводов.
- Вместе с функциями обновляйте инструкции, параметры и ссылки; при удалении документа убирайте все ссылки на него.

## Проверки

Из корня репозитория выполните [общие проверки](docs/README.ru.md#проверки-разработчика), затем тесты затронутых игр.
Для проверок Ren'Py укажите путь к своему SDK.

- Изменения компилятора, патчей, установки файлов и изображений покрывайте соответствующими тестами.
- Шрифты, переносы и сенсорное управление требуют также тестов Ren'Py и визуальной проверки.
- Для документации проверьте ссылки, якоря, блоки кода, фактический `--help` и `git diff --check`; полное прохождение не требуется.
- Разделяйте результаты тестов, lint, статического анализа и устройств. Успешная генерация не равна проверке всех маршрутов.

## Git и полномочия

- Независимые проверенные задачи коммитьте отдельно, включая только относящиеся к ним файлы.
- Отправка изменений, релизы, смена версии и повышение системных требований требуют явного запроса.
- Новые ветки создавайте с префиксом `codex/`; не переключайте ветку без причины.
- Не запускайте неизвестные EXE, не выполняйте административные действия и глобальную установку без разрешения.
