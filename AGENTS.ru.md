# Правила работы над проектом

[中文](AGENTS.zh.md) | [English](AGENTS.en.md) | [Русский](AGENTS.ru.md)

## Начало работы

- Проверьте Git и сохраните существующие изменения пользователя. Ищите через `rg`.
- Прочитайте README проекта и затронутой игры. Примеры путей — в
  `local.paths.example.toml`, локальные пути — в игнорируемом `local.paths.toml`.
- Для межрепозиторной задачи прочитайте также AGENTS.md LiarsoftTool.
  Преобразование ресурсов относится к LiarsoftTool, компиляция TSC в Ren'Py,
  runtime и интерфейс — к этому репозиторию.

## Границы реализации

- Общий код — в `runtime/` и `port_template/`, диалекты и различия — в адаптерах.
- Не создавайте долгоживущие копии общих модулей и не исправляйте установленный
  код строковыми подстановками. Исправления должны попадать в генератор или шаблон.
- Неизвестное поведение подтверждайте EXE, сценарием и оригиналом именно этой игры.
- Оригиналы только для чтения. Преобразования — на копиях, тесты — во временных
  проектах. Не коммитьте ресурсы, готовые проекты, сохранения, ключи и личные пути.
- До перезаписи проверьте ручные изменения и правила генератора. Не устанавливайте
  административные зависимости автоматически и не запускайте неизвестные EXE.

## Документация

- README предназначен пользователю: назначение, зависимости, ресурсы, команда
  сборки, патчи и необходимые ограничения.
- Языковые версии лежат рядом как `.zh.md`, `.en.md`, `.ru.md`; исходный `.md`
  служит только навигацией. Все собственные документы проекта должны иметь полные,
  синхронные китайскую, английскую и русскую версии. Исходные лицензии и оригинальные
  сторонние юридические тексты сохраняются без перевода.
- За основу берите китайский текст пользователя; английская и русская версии передают те же сведения.
- Пишите короткие прямые инструкции. Детали обработки ошибок, миграции старых данных,
  внутренние поля, журналы регрессий и коммитов не относятся к пользовательскому руководству.
- Разделы README игры: обзор, ресурсы, сборка, языковые патчи, использование, проверки и ограничения.
- Хеши, адреса, таблицы параметров и основания реализации храните в технических
  заметках. Отделяйте статический анализ от реального прохождения.
- Главный README ссылается на игры. Каталог документации отделяет руководства от анализа.
- Проверяйте параметры, примеры и ссылки; удалённые функции не должны оставлять
  инструкции. Сохраняйте смысл лицензий, авторство и происхождение.

## Проверка

- Для документации проверяйте ссылки, заголовки, параметры и `git diff --check`;
  полное прохождение ради текста не требуется.
- Общий код: `tests/test_runtime.py`, `tests/test_port_template.py`.
- Установка файлов: `tests/test_file_install.py`; изображения: `tests/test_native_images.py`.
- Компиляция и патчи: `tests/test_tsc_compiler.py`, `tests/test_tsc_patches.py`.
- Общий проект: `tests/test_shared_port.py <SDK> --logic-only`, плюс тесты затронутой игры и lint.
- Текст и сенсорное управление: `tests/run_native_text_wrap.py`, `tests/run_touch_controls.py`.
- Изображение, звук, маршруты, старые сохранения и Android проверяются в игре.
  В отчёте различайте автоматические проверки и реальную работу на устройстве.

## Git

- Независимую проверенную задачу коммитьте локально, только её файлы. Если пользователь
  просит не коммитить, следуйте этому указанию.
- Без явного запроса не отправляйте изменения, не публикуйте Release, не повышайте
  версию или требования Android.
- Используйте текущий checkout; новые ветки при необходимости имеют префикс `codex/`.
