# Техническая справка: шрифты Forest

[中文](FOREST_FONT_ANALYSIS.zh.md) | [English](FOREST_FONT_ANALYSIS.en.md) | [Русский](FOREST_FONT_ANALYSIS.ru.md) | [日本語](FOREST_FONT_ANALYSIS.ja.md)

[Документация](README.ru.md)

Основания выбора шрифтов и метрик смешанного текста. Игрок меняет шрифт в настройках.
Выводы ограничены этими файлами и адресами.

## Статический анализ

Forest/Forest_CHS_unpacked.exe, PE32 x86, SHA-256
`94ab25e356d24d9a816ba7bcee6cb30fd6d0f664bbdbc24c000346b2f1b4bda9`.
EXE не запускался, фактически выбранный Windows GDI шрифт не перехватывался.

- `0x46336c`: BA DA CC E5 00 — CP936 «黑体».
- `0x46337c`: 82 6C 82 72 20 96 BE 92 A9 00 — CP932 «ＭＳ 明朝».
- Конструктор `0x43c48f` задаёт [esi+0x19c]=0; `0x438d3b` проверяет его:
  по умолчанию `0x438da2` запрашивает 黑体, другая ветвь `0x438d6f` — ＭＳ 明朝, не Songti/Noto.
- Глифовая функция `0x445e70` вызывает CreateFontA в `0x445ebc`: высота из размера,
  ширина/поворот 0, вес 0 или 700, charset 134 (GB2312_CHARSET), без отдельного сжатия английского.
- Около `0x446019` кэшируется advance: двухбайтные символы в `0x446042–0x446047` имеют ширину размера,
  однобайтные в `0x446052–0x446055` — половину; не произвольную пропорциональную ширину латиницы.

VA проверены rabin2 -i и radare2 -e bin.relocs.apply=true по строкам, вызовам и инициализации.
Значение ширины 0: [Microsoft CreateFontA](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-createfonta).

## Шрифты репозитория

port_template/fonts/simhei.ttf взят из /usr/share/fonts/truetype/winfonts/simhei.ttf, не из EXE.
SimHei Regular 5.04: [хеш и лицензия](../port_template/fonts/SimHei-NOTICE.ru.md).
В em 256 единиц: латиница/ASCII-пробел имеют advance 128, CJK — 256.
При 22px теоретически без hinting это 11/22px, близко к сетке движка. В местном Ren'Py hinting FreeType
даёт a/t 12px, остальным проверенным буквам 11px. Runtime берёт итоговые метрики Ren'Py,
без догадок о сжатии, East Asian Width или отрицательных интервалах.

Генератор копирует шрифты и уведомления. SimHei остаётся выбором меню. После тестов 2026-10-03
шрифт основного текста по умолчанию возвращён к Noto Sans CJK JP Regular; изображения имён не менялись.
Старое значение SimHei мигрирует один раз, другие выборы сохраняются; SimHei можно выбрать снова.

## Границы проверки

Проверяются копирование, миграция значений и реальные метрики Ren'Py, lint проверяет сценарии.
Это не доказывает одинаковые глифы, hinting, базовую линию и интервалы GDI/FreeType.
Разрывы смешанного текста сравниваются вручную; версии шрифта и подстановка Windows могут различаться.
Без динамического захвата нельзя утверждать побайтовую идентичность шрифта оригиналу.

В Ren'Py 8.5.3 при 22px, 19 ширинах, интервале 7px строка
«之后，我俩跑到Royal Host餐厅，就桃色电影» разрывалась после 电, оставляя 影 отдельно.
С последующими явными переносами — четыре строки, высота 120px. Выбор запрошенного шрифта не устранил все различия.
Тесты сохраняют пропорциональный Noto и измерения Wiki-тегов.

## Смешанный текст и текущее значение

В SDK font.py по умолчанию FreeType auto hinting. Режимы SimHei auto-light/bytecode/none
уменьшают Royal Host со 112 до 110px, но 影 всё равно начинается на границе 19 знаков.
Правило < не менялось; нет сжатия, отрицательных интервалов, расширения строки или удаления ^n.
Сравнение существующих шрифтов при 22px по запасному варианту пользователя:

| Шрифт | Ширина Royal Host | Знак CJK | Строк в примере |
| --- | ---: | ---: | ---: |
| SimHei Regular（auto） | 112px | 22px | 4 |
| Noto Sans CJK JP Regular | 106.703125px | 22px | 3 |
| Noto Sans CJK Light | 105.796875px | 22px | 3 |
| Noto Serif CJK Regular | 114.6875px | 22px | 4 |

Regular sans-serif сохраняет вес ближе к Hei вместо Light ради ширины. С новым Noto Regular
影 начинается около 414.7px < 418px и естественно помещается по существующему правилу:

```text
之后，我俩跑到Royal Host餐厅，就桃色电影
高谈阔论，一直聊到第二天黎明时分，才在
乌鸦的喧闹声中作别。
```

Wiki on/off не меняет разрывы. Это нативная раскладка, не сравнение реальных снимков окна.
Другие тексты, выбранные шрифты, крупные размеры и Android ещё проверяются вручную.
