# SevenBridge: данные исходной программы

[中文](NATIVE_EVIDENCE.md) · [Руководство](README.ru.md)

Дата анализа: 2026-10-22. Исследован японский `SBridge_jp.exe`, PE32/i386,
базовый адрес `0x400000`, SHA-256:

```text
c7d5fc38cf0c354a61d056b607cf1367b2529557e9e0407d0b0fdf12771b35e3
```

Это статический анализ файла и псевдокода Ghidra, а не наблюдение запущенной
игры. Исходные файлы не изменялись, EXE не запускался. Все адреса виртуальные.

## Ресурсы и запуск

В исходном `scr.xfl` находятся 111 GSC. Прежние 112 TSC в распакованном каталоге
не служат эталоном: сценарии нужно заново экспортировать текущим LiarsoftTool.
Контейнер — `modern-36`; таблица аргументов выбирается отдельно для каждого
файла по метаданным `rscript18`, `rscript19` или `modern`.

`0000` выполняет инициализацию и переходит к `0001`. Начало игры ведёт через
`0100 → 0110 → 2001`. Галереей CG управляют `0201–0208` и `0210`, повтором сцен —
`0301/0302/0310` и `5001–5013`, музыкой — `0400/0401`.
Резервное меню `top_me*` из EXE не заменяет эти сценарные экраны.
Исходное главное меню сохраняется; его настройки открывают Text Settings.
Сопровождающий подтвердил возврат к миниатюрам после
последнего CG. Обёртка просмотра возвращает управление странице из `r[299]`,
не меняя результат регистра в команде `hit`.

`APINI` расположен по адресу `0x469740`; инициализация `0x41a260` использует его
размер экрана 800×600 и пути ресурсов. `0x41ab90` сначала ищет `RsInit.cfg`, затем
`RsInit.dll`. В исследованной установке их нет, поэтому действует конфигурация EXE.

## Команды и состояние

| Реализация | Исходная программа |
| --- | --- |
| Диспетчер команд | `0x41cc40`, команды и VM различаются по старшим битам |
| `locmode` с тремя аргументами | case `0x26 → 0x420220`; объект 0 означает все обычные объекты |
| `folder 0` | `0x4204e0`, меняет каталог объектов 1–49 |
| Один канал эффектов | cases `0x3e/0x3f/0x40`, читают 1/3/1 выражения |
| `getflag` | case `0x72 → 0x421670`, номер и режим |
| Запись просмотренного CG | `0x41fcc0`; отдельный бит записывается всегда, `r[9000+номер]` — только при номере меньше 1000 |
| Снимок обычных регистров | `0x41a260/0x41b070`, 7000 регистров по 16 бит |

При нулевом режиме `getflag` читает бит прогресса в `r[0]`; ненулевой режим
устанавливает бит, сохраняя `r[0]`. Номер приводится к беззнаковым 16 битам.
`0x41b450/0x41b470` обращаются к bank 0 через `0x424110/0x424190`.
Той же таблицей пользуется `gload`. В порте её хранит `persistent.seen_cg`,
входящий также в резервную копию прогресса.

## Текст и звук

`0x414990` загружает компоненты `tboxNN`. Размер `tbox00` — 800×130,
текстовая область — 682×119 в `(0,11)`, индикатор ожидания — `(690,102)`.
Ширина изображений имён `gfNNN` — 146. Геометрия сохраняется в `.meta.xml`;
порт рисует имя и реплику отдельно.

`0x413f70` создаёт текстовую панель, `0x415050(this,0x80)` задаёт прозрачность
её фона. В настройках светлое изображение означает выбранное состояние,
тёмное `*_f` — невыбранное.

`0x41b0b0` записывает `r[1]`, `r[2]` и `r[3]` в заголовок сохранения.
`0x4037d0` выбирает `dt1_` и `dt2_` по данным сохранения, а не текущему прогрессу.
Префиксы находятся по адресам `0x469160` и `0x469158`. В этой игре главы оформлены
как `dt2_*`, поэтому сохраняется также `r[2]`. Файлы `nonbl` для 1–9 используют
полноширинные цифры, для 10 — обычные. Размер холста и смещение берутся из `.meta.xml`.

`0x41b5b0` делит номер голоса на группы по 10000: группа 0 читает
`voice/%04d.wav`, остальные — `voice/<группа>/%04d.wav`. После преобразования
используется одноимённый OGG, обычный PCM WAV сохраняется как есть.
В `0x4218d0` параметр повторения `999` означает цикл.

Проверка 2026-10-23: исходный `mov` содержит `0002.mpg`, `0003.mpg` и
`0004.mpg`; ранее этот каталог не попал в преобразованную копию ресурсов.
Все три файла содержат видео MPEG-1 и звук MP2. Обработчик запуска
`0x4238a0` ссылается на `mov/0002.mpg` и `mov/0001.mpg` по адресам
`0x4238eb/0x42390e` и вызывает проигрыватель `0x445240`. Порт использует
общий порядок `(2, 1)` и пропускает отсутствующий `0001`.
Сценарии `0110/0302` вызывают видео 3 и 4, а `2004` — видео 2.
Сборка копирует `mov/*.mpg` и сохраняет эти команды.

`ev_177a58fd85e2021bd3409f818451f41c36da4a3b309aa5a2872d1d5d49969876`;
инструкции GNU objdump:
