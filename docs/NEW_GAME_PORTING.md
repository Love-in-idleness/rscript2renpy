# 新游戏移植指南

本指南用于开发尚未支持的 CodeX/RScript 游戏适配，不是通用的一键移植命令。
已有游戏直接按 [环境配置](SETUP.md)及对应游戏 README 构建，不需要 AI。
相似的 TSC、目录或 opcode 编号不证明引擎语义相同。

## 开始前准备

- 游戏名称、准确版本、已安装更新/特典、原始 EXE 及其哈希。
- 合法持有的原版和补丁原件，以及可写的转换副本。
- 两个代码仓库、LiarsoftTool CLI、Ren'Py SDK 和新的输出工程路径。
- 原游戏可供比较的启动、首段剧情、菜单和特殊功能表现。

编码、TSC 字节布局和命令方言是独立信息。先核对当前 TSC 声明及上游输出，
不能通过年份、语言标签或另一款游戏的格式猜测。原始 EXE 是未知语义的重要
证据；只读分析不必执行 EXE。需要执行未知程序时另行确认环境和权限。

## 工作分层

| 位置 | 负责内容 |
| --- | --- |
| LiarsoftTool | 归档、GSC/TSC、图像/音频转换和输入编码 |
| `runtime/` | 已验证的通用 RScript 指令、寄存器、图层、音频和文字行为 |
| `port_template/` | 公共编译、资源装配、元数据布局、菜单及平台配置 |
| `<slug>/` | 游戏方言、版本验证、入口、专属行为及 README |
| 输出工程 | 生成结果，不是持久修复的唯一位置 |

从 [通用模板](../port_template/README.md)和
[分层约定](SHARED_TEMPLATE_MIGRATION.md)开始。调用现有编译及装配接口，
不要复制一套公共运行时长期分叉；模板安装器本身不是新游戏适配器。
跨仓库修改先阅读双方 `AGENTS.md`，验证生产者输出和消费者解析。

## 推进与验收

1. 审计输入：版本、编码、schema、方言、入口、opcode、资源和元数据。
   记录已确认、不支持和未知项；未知指令不能静默删除。
2. 完成启动、标题和第一段剧情：同时确认文本、背景、立绘、音频和选择。
3. 完成菜单、存读档、回滚边界、持久化、鉴赏及返回流程，再扩大路线覆盖。
4. 为新增行为添加小型回归测试；通用改动同时检查已有游戏，尤其 Forest/Khime。
5. 写可重复执行的生成器和游戏 README。Android 构建与实机验收另列阶段。

重点对照：图片原点与锚点、深度和透明度、队列清理、转场时长；语音与 SE
通道、编号、循环和停止；`TXT/TXA/font`、文本控制符、注音同步、横竖排及
等待图；标题返回、存档权限、全局 flag 和鉴赏结束后的状态复原。
`.meta.xml` 给出几何信息，不会自动证明未知控件的动作。

证据笔记可放在游戏目录的 `NATIVE_EVIDENCE.md`，注明 EXE 哈希、函数地址或
脚本位置、实现范围与未确认部分。有意降级的效果保留原值及原因。
不提交原 EXE、剧本或游戏素材来代替证据说明。

## 可复制的 AI 提示词

填写以下占位项后交给能访问本机文件与终端的 AI 编程工具。
路径必须明确，不能依赖维护者机器的目录或 `rebuild_local.sh`。

```text
请使用 rscript2renpy 移植一个新的 CodeX/RScript 游戏。

项目资料：
- 游戏名称：<名称>
- 适配目录名：<slug>
- 游戏版本及已安装特典/更新：<准确说明>
- 原始资源目录：<路径，只读>
- 原游戏 EXE：<路径，只读>
- 资源转换副本：<路径，允许写入>
- 可选语言补丁及语言标签：<例如 zh=路径；没有则写无>
- rscript2renpy 仓库：<路径>
- LiarsoftTool 仓库与 CLI：<路径>
- Ren'Py 8 SDK：<路径>
- 输出工程：<新的路径>

目标：
在 rscript2renpy/<slug>/ 实现生成器，使其他拥有同版本正版游戏的用户，
能按 README 自行构建可运行工程。运行时只负责 TSC，不直接处理 GSC。

先阅读相关 AGENTS.md、README、docs/SETUP.md、docs/NEW_GAME_PORTING.md
和公共模板说明，检查 Git 状态，保留已有修改。核对游戏版本、EXE 哈希、
当前 TSC 格式、编码、入口、资源目录及 .meta.xml，列出已支持、未知和
需要逆向的功能，再开始实现。

实现规则：
1. 原始资源和补丁原件保持只读；解包转换只在副本进行。转换错误从
   LiarsoftTool 修复，不能在生成器中掩盖错误或硬编码错误导出的地址。
2. 优先复用 runtime 和 port_template。通用修复写公共层，游戏差异写
   适配目录；不能只修生成工程，也不能对复制后的公共代码做字符串补丁。
3. 不能复用的语义根据本游戏 EXE、脚本和原游戏表现验证。不要因为另一款
   游戏相似就猜测效果；TSC 字节格式不自动决定命令方言或动画时序。
4. 处理图片定位、裁剪、透明度、立绘、深度、转场和清理；音乐、语音、
   音效及等待；文本控制符、注音、排版、姓名牌、文本框和等待图；选择、
   菜单、存读档、回滚边界、持久化与鉴赏。启动视频与标题返回分别验证。
5. 只支持当前 TSC 格式。未知 opcode、版本不匹配和未确认行为记录证据及
   影响，不静默忽略、不编造实现。需要视觉判断时可向我询问。
6. 不提交游戏资源、生成工程、存档、签名密钥或本机路径。覆盖已有人工
   修改前确认。没有许可不安装管理员依赖或执行未知 EXE。

推进顺序：
先完成启动、标题和第一段剧情，确认背景、立绘、文本、语音与选择；再完成
菜单、存读档、持久化和鉴赏；最后扩大剧情覆盖。安卓打包另行处理。

交付要求：
- 提供接受资源目录和输出目录的生成器，以及清晰的 --help。
- 在 <slug>/README.md 写支持版本、环境、资源准备、语言补丁、构建命令、
  已知限制和验证边界，并从主 README 链接；不同游戏的补丁规则不要混用。
- 在游戏目录记录原生证据和未确认项；不承诺适配未分析的 EXE 版本。
- 新增行为有测试；公共改动检查已有端口。分开报告静态分析、自动测试、
  Ren'Py lint、画面验证、实际游玩和 Android 实机结果。
- 每项独立任务验证后及时本地 commit。未经明确要求，不 push、不发 release。
```

## 最小交付检查

在仓库根目录执行公共检查；新游戏还需自己的测试和生成工程 lint：

```bash
python -B tests/test_runtime.py
python -B tests/test_port_template.py
python -B tests/test_shared_port.py /path/to/renpy-sdk --logic-only
git diff --check
/path/to/renpy-sdk/renpy.sh /path/to/new-project lint
```

验收时单独列出已覆盖场景、未实现功能和是否人工运行。上述共享测试使用隔离
工程，不验证新游戏全流程；lint 成功也不证明音频、画面、旧存档或完整路线正确。
最终 README 应使另一台机器上的用户能复现，而不是依赖开发者输出目录中的
手工修补。代码和现有例外资产的授权边界见
[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。
