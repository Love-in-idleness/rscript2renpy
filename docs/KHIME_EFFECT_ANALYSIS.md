# Khime 对象效果静态分析

依据用户持有的 `KhimeDL_CHS.exe`，不分发可执行文件。
SHA-256：`522bec3e93340ffd3bdb24ba98cfb775f80df9d85460819da840d824ad4822a8`。
PE32，ImageBase `0x400000`；以下均为虚拟地址。

`load` 经 `0x422d70 → 0x4218d0 → 0x4064f0`，`font` 经
`0x422e20 → 0x421a00 → 0x4066f0`，共同进入 `0x4070b0`；
`cls` 经 `0x423080 → 0x421b30 → 0x406790` 进入 `0x407ec0`。
因此文本对象与图片共用效果，不应把所有非零 `_oload` 效果归零。

| 参数 | load / cls 分支 | 确认语义与公共实现 |
| --- | --- | --- |
| 3 | `0x407218` / `0x407f7a` | renderer 2，alpha 步长 32；沿用普通淡入淡出 |
| 4 | `0x40724a` / `0x407fae` | renderer `0x12`，步长 32；沿用点阵过渡 |
| 10 | `0x4073da` / `0x4081ed` | 从下进入 / 向下移出；原生移动过渡近似轨迹 |
| 15 | `0x40771d` / `0x408485` | renderer 4，步长 16；保留 alpha 的白色 RGB 渐变 |
| 19 | `0x4077f9` / `0x40854e` | renderer 2，步长 8；普通淡变的四倍时长 |

renderer 4 经 `0x436c2e → 0x439d60`，将 RGB 混向白色。
附带的 vtable `+0x40/+0x44` 调用指向 `0x407d60`（`ret 4`），
不能据参数 20 推断缩放。

`_effect` 的 `0x4235a0` 按 Mode 选择 renderer：
Mode 1 的 `0x67 → 0x43b0f0` 以遮罩零红色区域反转目标 RGB；
其他模式的 `0x68 → 0x43b1f0` 是中灰亮度混合。
公共 shader 增加目标反色混合；Mode 0 沿用既有亮度混合近似。
Khime 实际资源名为大写 `ES101.png` 等，生成兼容检查必须忽略文件名大小写，
但保留真实路径；无需复制或重命名资源。

实现基于已有 effect 3 的 0.5 秒基准：19 为 2 秒、15 为 1 秒。
原版帧间隔、移动加速度和逐像素舍入尚未复现，需人工视觉确认；
静态分析和 lint 不等于原版视觉一致。未确认效果继续扁平化并注释。
效果 0 的文本对象保留既有 Forest 淡入行为。

自动验证：`python3 -B tests/test_shared_port.py /opt/apps/renpy`，
在独立测试工程检查真实 shader 编译、反色/白色像素、队列执行和文本对象效果。
人工对照入口：1102（19）、1110（文本 4）、7501（clear 10）、7503（load 15）。
