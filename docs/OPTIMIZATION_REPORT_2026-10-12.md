# 两仓库安全与执行路径优化完成说明

日期：2026-10-12。

## 完成状态

计划中的四项实现已完成。两个仓库仍独立维护，没有改动游戏 opcode 语义、
TSC 格式或现有命令行选项，没有大规模重组模块，也没有新增依赖。
本轮仅本地提交，没有推送、打 tag、发布或提高版本号：
LiarsoftTool 保持 2.2.3，rscript2renpy 保持 1.4。

| 计划项 | 实现位置 | 状态 |
| --- | --- | --- |
| 旧 GSC/TXT 安全边界 | LiarsoftTool 的 gscfile、transfile、bigendian、fileio | 完成 |
| CLI/GUI 公共转换分发 | LiarsoftTool 的 conversion 模块、CLI 和 GTK 调用处 | 完成 |
| 两仓库文件级安全写入 | LiarsoftTool 的 fileio；本仓库的 file_install、安装器及构建入口 | 完成 |
| 减少重复复制 | 本仓库的 file_install、资源安装、脚本/配置写入及 refresh_tsc | 完成 |

“实现完成”不等于所有既有游戏问题已经清零。Khime 的严格 lint 仍有三项
既有重复 default 诊断，详见下面的验证结果。

## 实际改变

### 1. 旧 GSC/TXT 读写

文件入口复用检查式读取，流接口保留，并检查定位、长度和短读。
解析时校验头部、区段长度、每个字符串偏移和 NUL 终止符；范围检查使用
差值或更宽的整数，避免检查本身溢出。

空字符串列表可以正常序列化。每个字符串只编码一次，编码结果同时用于长度
计算和写入。无法用目标编码表示的译文、带有内嵌 NUL 的译文明确报错，
不会悄悄替换成问号，也不会覆盖已有 GSC。

旧 TXT 路径的 GSC 解析器与结构化 GSC/TSC 解析器没有合并。
允许合法的重复偏移，也不再把“零号字符串必须为空”当成格式前提。

### 2. 公共转换分发

CLI、GTK 和相关测试直接调用非 GUI 的 conversion 模块。
CLI 不再保留逐格式转换的第二套实现，只负责参数、通配符、方向筛选和日志。
公共结果只有警告列表与 PCM 原样保留标志，没有新增数量、尺寸或通用回调接口。

成功日志采用操作类型、输入和输出路径；PCM 保留时明确表示没有生成 OGG。
警告、错误、退出码及递归/双方向筛选约定保留。

### 3. 文件级安装与输入保护

新内容写入目标目录内独占创建的临时文件，检查完整写入、刷新和关闭后，
才替换目标。不会先删除旧文件再改名。
Windows 使用同卷替换，不启用跨卷复制回退。

写入、关闭或替换失败时，旧内容保持完整，临时文件清理。
常规权限位、只读约定、覆盖许可、换行及来源时间戳规则保留；
私有权限在临时文件写入内容之前设置。

Python 复制、脚本、配置及转换图像复用文件级安装逻辑。
构建前拒绝输入资源/补丁与输出工程相互包含、相同，或通过内部文件/目录
符号链接指向输出工程。检查发生在写入工程及清理语言目录之前；
目录链接环通过已访问目录集合终止。

### 4. 增量安装

复制先比较文件大小，再按 64 KiB 分块比较，不同时加载两份完整音视频。
相同内容不重写；copy2 类型的安装仍同步来源元数据。
生成文本、配置和转换图像内容相同时也不替换文件。

相同内容的源码安装仍清理对应 .rpyc；没有借此引入编译缓存、
构建数据库或插件框架。各游戏的适配策略未重写。

2026-10-12 复核结果：

| 检查 | 结果 |
| --- | --- |
| Linux CTest | 11/11 通过，包含 GTK 冒烟、目录递归及失败注入 |
| Windows 交叉编译与 Wine | 10/10 通过，包含 GTK 冒烟和目标锁定导致的替换失败 |
| Python 公共测试 | runtime、port_template、file_install、tsc_compiler、tsc_patches、refresh_tsc 通过 |
| 文件级失败测试 | 写入、刷新、关闭、替换失败保留旧内容及时间戳，清理临时文件 |
| 权限及重复安装 | 只读目标拒绝改写；相同文件保持 inode/mtime，源码缓存仍清理 |
| 输入保护 | 相同/包含路径、根目录链接、内部目录/文件链接、链接环回归通过 |
| Forest/Khime 最小工程 | 生成及重复构建通过；Ren'Py SDK 独立运行回归通过 |
| Forest 严格 lint | 通过 |
| Khime 严格 lint | 已执行；仍有下列三项既有错误，不标记为全部通过 |

Wine 的 CTest 未运行宿主 CMake 直接启动 Windows EXE 的 directory_packing
用例；该用例由 Linux 回归覆盖。Wine 通过不等于 Windows 实机验收。
所有生成和运行测试使用临时工程与隔离存档，没有启动正式游戏或改写玩家存档。

Khime 的既有重复声明为：

- persistent.rscript_say_line_chars：options.rpy 与 00_rscript_wrap.rpy。
- persistent.rscript_text_size：options.rpy 与 text_features.rpy。
- persistent.rscript_line_spacing：options.rpy 与 text_features.rpy。

共享工程测试只识别这三项已知诊断，不把它们当作 lint 成功；
出现其他游戏路径诊断会使检查失败。本轮按边界保留游戏默认值逻辑，
没有为了消除 lint 修改这些声明。

### 有效资源对照与输出差异

用修改前的旧 GSC/TXT 实现作基线，Forest 的 103 个、Khime 的 341 个
GSC→TXT 输出逐字节一致，共 444 个样本。

test/gsc 的 103 个样本中，91 个相同，12 个不同。旧实现对这些字符串
按相邻长度顺序读出，会带入额外字节或 NUL；新实现按实际偏移及终止符读取。
这项差异已明确保留，不恢复旧的误读行为。测试资料和原版资源没有改写，
导出及对照文件仅在临时目录中。

## 明确保留的边界

- 只做文件级保护，不暂存整语言包、不提供整工程事务。
  语言目录依然清理后重建，失败时可能不完整；修复报错后必须重新构建。
- 不承诺断电、网络文件系统或多个构建器同时写同一工程时的事务安全。
- 替换不会保留旧文件的硬链接关联；高级 ACL/所有权元数据未做专项回归。
- 没有改动文字、特效、游戏专属逻辑，也没有重建正式移植工程或打包 APK。
- 完整路线、原游戏视听一致性、旧存档及 Windows/Android 实机由用户验收。

后续若继续开发，Khime 默认值去重应作为独立任务，确认保留已有玩家偏好和
游戏默认值之后再处理；它不是本轮文件安全优化的遗漏。
